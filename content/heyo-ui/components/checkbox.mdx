# Checkbox

Pass `label` and `Checkbox` renders the whole clickable row — box, label,
description, and the `<label>` wrapping that makes all of it a hit target.
Without one it renders just the box, for a table's select column or a custom
layout; give it an `aria-label` in that case.

## Usage

```tsx
import { Checkbox } from "@heyo-sh/heyo-ui";

<Checkbox label="Send deploy notifications" defaultChecked />;
```

## Indeterminate

The third state exists for one reason: a header checkbox above rows where only
some are selected. [`useSelection`](/utilities) computes it for you.

<Callout type="note" title="Checkbox or Switch?">
  A checkbox is a value you are editing and will submit — it belongs in a form.
  A [`Switch`](/components/switch) applies immediately, which is why it belongs
  in settings.
</Callout>

## Properties

<Properties>
  <Property name="label" type="ReactNode">
    An inline label next to the box. Its presence turns the component into the
    whole clickable row.
  </Property>
  <Property name="description" type="ReactNode">
    Muted helper text under the label.
  </Property>
  <Property name="checked / defaultChecked" type="boolean">
    Controlled and uncontrolled state.
  </Property>
  <Property name="onCheckedChange" type="(checked: boolean) => void">
    Fires when the box is toggled.
  </Property>
  <Property name="indeterminate" type="boolean">
    The mixed state, for a header checkbox above a partial selection.
  </Property>
  <Property name="disabled" type="boolean">
    Dims the row and ignores interaction.
  </Property>
  <Property name="wrapperClassName" type="string">
    Class for the outer `<label>`, used when a label or description is given.
  </Property>
  <Property name="className" type="string">
    Class for the box itself.
  </Property>
  <Property name="name / required / value" type="—">
    Standard form behaviour, passed through to Base UI.
  </Property>
</Properties>
