# Card

`Card` is the box every grouped surface in an application is built from. The
parts are independent: a card can be a header and a body, a body alone, or all
three. Seams are only drawn where something actually follows, so a header
without a body carries no stray rule.

Every slot keeps its own padding, which is what lets a table or a list sit
flush inside one — drop `p-0` on `CardBody` and the rows run edge to edge.

## Usage

```tsx
import { Card, CardBody, CardHeader, CardTitle } from "@heyo-sh/heyo-ui";

<Card>
  <CardHeader>
    <CardTitle>Usage</CardTitle>
  </CardHeader>
  <CardBody>142,318 requests this month.</CardBody>
</Card>;
```

## Variants

`flat` is the default and the right answer in a dense interface: a hairline is
enough to separate a surface from the page. `raised` adds a real edge and a
whisper of shadow for something that floats. `recessed` is a well — logs,
diffs, empty states. `plain` keeps only the layout. Hierarchy comes from the
surface, not from a border.

## The header is a row

`CardHeader` is a flex row with `justify-between`, so a title on the left and a
control on the right need no extra wrapper. Group the title and description in
one element when both are present.

## Body only

A card does not need three slots. One `CardBody` is the whole component when
the content is a single figure.

## The footer is for actions

`CardFooter` sits on the elevated surface and right-aligns its children, which
is where a card's actions belong. It is not a second body — long content in a
footer means the card wants another section instead.

<Callout type="note" title="Pairs well with">
  [`Stat`](/components/stat) is borderless by default so it can live inside a
  card. [`Empty`](/components/empty) fills a card body that has nothing in it
  yet.
</Callout>

## Properties

### Card

<Properties>
  <Property name="variant" type='"flat" | "raised" | "recessed" | "plain"'>
    The surface treatment. It defaults to `flat`.
  </Property>
  <Property name="className" type="string">
    Merged through `tailwind-merge`, so a different radius or width is one
    class.
  </Property>
  <Property name="children" type="ReactNode">
    Usually `CardHeader`, `CardBody` and `CardFooter`, in that order.
  </Property>
</Properties>

### CardHeader, CardBody, CardFooter

<Properties>
  <Property name="children" type="ReactNode">
    `CardHeader` lays its children out as a row with the last item pushed right.
    `CardBody` is the content column. `CardFooter` right-aligns actions on the
    elevated surface.
  </Property>
  <Property name="className" type="string">
    Merged into the respective part — `p-0` on `CardBody` is how a table or a
    list sits flush. Every part also carries a `data-slot` (`card-header`,
    `card-body`, `card-footer`) for global overrides.
  </Property>
</Properties>

### CardTitle and CardDescription

<Properties>
  <Property name="children" type="ReactNode">
    `CardTitle` renders an `<h3>` at 13px medium; `CardDescription` renders a
    12px muted paragraph. Both have their margins reset.
  </Property>
</Properties>
