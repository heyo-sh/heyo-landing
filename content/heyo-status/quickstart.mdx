# Quickstart

Use `create-heyo-status` to create a complete status page. The generated project
includes the framework routes, database setup and scheduler wiring for the
selected deployment. Installing the library alone does not set up monitoring.
You'll need Bun 1.4.3+ for the generated `dev` and CLI scripts, even if you
install packages with npm, pnpm or Yarn.

## Create a project

Choose a framework, theme, deployment target, database and package manager when
prompted. Cloudflare uses D1, Vercel uses PostgreSQL, and **Configure later**
supports SQLite or PostgreSQL for self-hosting.

<CodeBlockGroup defaultValue="bun" variant="line">
  <CodeBlock language="bash" title="bun">
    {`bun create @heyo-sh/heyo-status`}
  </CodeBlock>
  <CodeBlock language="bash" title="npm">
    {`npm create @heyo-sh/heyo-status@latest`}
  </CodeBlock>
  <CodeBlock language="bash" title="pnpm">
    {`pnpm create @heyo-sh/heyo-status`}
  </CodeBlock>
  <CodeBlock language="bash" title="yarn">
    {`yarn dlx @heyo-sh/create-heyo-status`}
  </CodeBlock>
</CodeBlockGroup>

## Start the page

Follow the commands printed by the creator. With Bun, for example:

```bash
cd my-status-page
bun dev
```

If you skipped dependency installation in the creator, install the project's
dependencies first. With SQLite or Vercel/PostgreSQL, `bun dev` starts a local
scheduler and runs the first check. Cloudflare/D1 projects migrate local D1
and start the framework dev server instead; deployed Workers use cron triggers.
The Cloudflare starter has no `check` or `db:seed` scripts.

Open the page, then replace the starter's `example.com` monitors before you
publish it. You don't need a global CLI install to start the generated app.

<Callout type="info" title="The config is the source of truth">
  The routes, scheduler and CLI use <code>heyo-status.config.ts</code>, which
  also contains the database path or connection string. Do not commit production
  tokens or credentials; configure them from a private secret source.
</Callout>

## Check that it works

With the project running, try its public endpoints (adjust the port for your
framework):

```bash
curl http://localhost:3000/api/heyo-status/healthz
curl http://localhost:3000/api/heyo-status/status/summary
```

`/healthz` does not verify the database or the scheduler; check the summary
after a check has run. With SQLite or Vercel/PostgreSQL, `bun run check` runs
a check on demand. Apply PostgreSQL migrations before deploying. With
Cloudflare/D1, follow the [Worker and Wrangler instructions](https://heyo.sh/heyo-status/deploying/cloudflare)
for local and remote migrations.
