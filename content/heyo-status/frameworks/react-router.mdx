# React Router

Use `create-heyo-status` for a Framework Mode project with the page, API,
database setup and scheduler wiring already connected. Choose Cloudflare
(D1 and Worker cron triggers) or Vercel (PostgreSQL and Vercel Cron) for a
production deployment. Installing only the library does not schedule checks.

## Create a project

Pass `react-router` to select the framework without a prompt. Omit flags to
choose a deployment, database and theme interactively.

<CodeBlockGroup defaultValue="bun" variant="line">
  <CodeBlock language="bash" title="bun">
    {`bun create @heyo-sh/heyo-status my-status-page --template react-router
cd my-status-page
bun dev`}
  </CodeBlock>
  <CodeBlock language="bash" title="npm">
    {`npm create @heyo-sh/heyo-status@latest my-status-page -- --template react-router
cd my-status-page
npm run dev`}
  </CodeBlock>
  <CodeBlock language="bash" title="pnpm">
    {`pnpm create @heyo-sh/heyo-status my-status-page --template react-router
cd my-status-page
pnpm dev`}
  </CodeBlock>
  <CodeBlock language="bash" title="yarn">
    {`yarn dlx @heyo-sh/create-heyo-status my-status-page --template react-router
cd my-status-page
yarn dev`}
  </CodeBlock>
</CodeBlockGroup>

The generated scripts and CLI require Bun 1.4.3+ even if you use another
package manager. If you skipped dependency installation, install the project's
dependencies first. Replace the example monitors in `heyo-status.config.ts`.
With Vercel/PostgreSQL, `bun dev` starts the local scheduler and `bun run check`
runs one check; Cloudflare/D1 uses Worker cron triggers in production instead.

## Customise the generated React Router project

- `heyo-status.config.ts` defines the database, monitors, schedule and theme.
- `src/routes.ts` and `src/routes/api.heyo-status.$.ts` expose the status API.
  If you change `basePath`, update the catch-all route too.
- `src/routes/_index.tsx` loads the current snapshot on the server;
  `src/root.tsx` loads the theme stylesheet and bootstrap script.
- The deployment overlay runs the three scheduled jobs. Keep its cron routes
  or Worker `scheduled` handler when changing the app.

On Cloudflare, use HTTP or DNS monitors: Workers cannot run native TCP/TLS
checks. On Vercel, those checks need Node.js 20.19+. See the
[Cloudflare](https://heyo.sh/heyo-status/deploying/cloudflare) and
[Vercel](https://heyo.sh/heyo-status/deploying/vercel) guides before deploying.
