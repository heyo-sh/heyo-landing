# Select

`Select` picks one value from a known list. Groups rule themselves off and
their labels stick while you scroll, so a long list never loses its headings.
The popup caps at `18rem` — or the space available, whichever is smaller — and
scrolls past that.

**It does not lock the page.** `modal` defaults to `false`, unlike Base UI:
picking a value from a list is not a modal task, and freezing the application
behind one is both surprising and, if the unlock ever misses, permanent.

## Usage

```tsx
import { Select } from "@heyo-sh/heyo-ui";

<Select defaultValue="fra" onValueChange={setRegion}>
  <Select.Trigger placeholder="Pick a region" />
  <Select.Content items={regions} />
</Select>;
```

## From data

`items` builds the list, and a nested `items` array becomes a titled group —
the same markup the example above writes by hand.

## Sizes and a field

The trigger takes the four control heights, and the whole thing drops into a
[`Field`](/components/field) when it needs a label.

## Multiple values

Pass `multiple` and the value becomes an array. For more than a handful of
options — or anything worth typing to find — use
[`Combobox`](/components/combobox) instead.

<CodeSnippet
  previewClassName="heyo-ui"
  code={`<Select multiple defaultValue={["fra", "waw"]}>
  <Select.Trigger placeholder="Pick regions" />
  <Select.Content items={regions} />
</Select>`}

## Properties

### Select

<Properties>
  <Property name="value / defaultValue" type="Value">
    Controlled and uncontrolled selection. With `multiple`, both are arrays.
  </Property>
  <Property name="onValueChange" type="(value: Value) => void">
    Fires when the selection changes.
  </Property>
  <Property name="multiple" type="boolean">
    Allows several values.
  </Property>
  <Property name="modal" type="boolean">
    Whether the open list locks the page. It defaults to `false`, unlike Base
    UI.
  </Property>
  <Property name="disabled / required / name" type="—">
    Standard form behaviour, passed through to Base UI.
  </Property>
</Properties>

### Select.Trigger

<Properties>
  <Property name="placeholder" type="string">
    Shown when nothing is selected.
  </Property>
  <Property name="size" type='"xs" | "sm" | "base" | "lg"'>
    Control height. It defaults to `base`.
  </Property>
  <Property name="children" type="ReactNode">
    Replaces the rendered value — pass `Select.Value` with a renderer for
    anything custom.
  </Property>
</Properties>

### Select.Content

<Properties>
  <Property name="items" type="SelectOption[]">
    Shorthand. An entry is `{ value, label, disabled }`, or
    `{ label, items }` for a titled group.
  </Property>
  <Property name="maxHeight" type="string">
    Cap on the popup height. It defaults to `18rem`; anything taller scrolls.
  </Property>
  <Property name="sideOffset" type="number">
    Gap between the trigger and the popup.
  </Property>
  <Property name="positioner" type="Select.Positioner.Props">
    Placement overrides.
  </Property>
</Properties>

### Items and groups

<Properties>
  <Property name="Select.Item" type="value, disabled">
    One option. The check mark is drawn for you.
  </Property>
  <Property name="Select.Group / GroupLabel" type="—">
    A titled section. It draws its own top rule, so consecutive groups separate
    themselves — no manual `Select.Separator` between them.
  </Property>
  <Property name="Select.Separator" type="—">
    A rule, for the rare case a group is not what you want.
  </Property>
  <Property name="Select.Value" type="children">
    The rendered value inside the trigger, when you need to format it.
  </Property>
</Properties>
