# Sidebar

`Sidebar` is the application chrome: a provider that owns the open state, a
panel composed from menus and groups, and an inset that holds the page. It
collapses to a rail of icons, toggles with `⌘B` / `Ctrl B`, and turns into an
overlay drawer below `768px` on its own.

It is deliberately **not a panel**. The sidebar shares the page background and
a single hairline separates it — a sidebar lighter than the page reads as
something floating on top of the application rather than part of it.

## Usage

```tsx
import { Sidebar } from "@heyo-sh/heyo-ui";

<Sidebar.Provider defaultOpen>
  <Sidebar>
    <Sidebar.Content>
      <Sidebar.Menu>
        <Sidebar.MenuButton icon={IconHome} active>
          Home
        </Sidebar.MenuButton>
      </Sidebar.Menu>
    </Sidebar.Content>
  </Sidebar>

  <Sidebar.Inset>{children}</Sidebar.Inset>
</Sidebar.Provider>;
```

`Sidebar.Provider` wraps **both** the sidebar and the page, because the inset
reacts to the same state.

## Nested sections

A branch is a `Sidebar.Collapsible` inside a `Sidebar.MenuItem`. `MenuButton`
wraps itself in an `<li>` by default, so pass `unwrapped` when you supply the
item yourself — as the trigger above does.

## Router links

Every menu button takes `render`, so a navigation entry becomes whatever your
router uses while keeping the row's styling, active state and icon slot.

```tsx
<Sidebar.MenuButton icon={IconHome} render={<NavLink to="/" />}>
  Home
</Sidebar.MenuButton>
```

## Collapsing

<Properties>
  <Property name="icon" type="default">
    Shrinks to a rail: labels and badges fade out, icons stay. The reader keeps
    a map of the application.
  </Property>
  <Property name="offcanvas" type="collapsible">
    Slides fully out of view. Use it when the content needs every pixel.
  </Property>
  <Property name="none" type="collapsible">
    Always expanded — for a sidebar that is the whole interface.
  </Property>
</Properties>

`Sidebar.Rail` turns the hairline seam into a click target, which is what makes
the whole thing feel like real application chrome rather than a navigation
list. Anything that should disappear with the labels gets
`group-data-[state=collapsed]/sidebar:hidden` — the search field in the first
example does exactly that.

## Reading the state

```tsx
import { useSidebar } from "@heyo-sh/heyo-ui";

const { open, setOpen, toggle, state, isMobile } = useSidebar();
```

Anything below the provider can read or drive it — a header button, a keyboard
handler of your own, a layout that shifts when the rail collapses.

## Properties

### Sidebar.Provider

<Properties>
  <Property name="defaultOpen" type="boolean">
    Uncontrolled initial state. It defaults to `true`.
  </Property>
  <Property name="open" type="boolean">
    Controlled state. Pair it with `onOpenChange`.
  </Property>
  <Property name="onOpenChange" type="(open: boolean) => void">
    Fires on every toggle, including the keyboard shortcut.
  </Property>
  <Property name="width" type="string">
    Expanded width, any CSS length. It defaults to `"15rem"`.
  </Property>
  <Property name="widthIcon" type="string">
    Collapsed rail width. It defaults to `"3.25rem"`.
  </Property>
  <Property name="shortcut" type="string | false">
    The key that toggles the sidebar together with ⌘ or Ctrl. It defaults to
    `"b"`; pass `false` to opt out.
  </Property>
  <Property name="mobileBreakpoint" type="string">
    The media query below which the sidebar becomes an overlay drawer. It
    defaults to `"(max-width: 767px)"`.
  </Property>
</Properties>

### Sidebar

<Properties>
  <Property name="side" type='"left" | "right"'>
    Which edge it sits on. It defaults to `left`.
  </Property>
  <Property name="collapsible" type='"icon" | "offcanvas" | "none"'>
    How it collapses. It defaults to `icon`.
  </Property>
</Properties>

### Sidebar.MenuButton and Sidebar.MenuSubButton

<Properties>
  <Property name="icon" type="IconLike">
    The leading glyph. It stays visible when the rail collapses.
  </Property>
  <Property name="active" type="boolean">
    Marks the entry as the current page.
  </Property>
  <Property name="render" type="RenderProp">
    Swaps the `<button>` for a link or a router component.
  </Property>
  <Property name="unwrapped" type="boolean">
    Skips the automatic `<li>` wrapper, for when you supply your own
    `Sidebar.MenuItem` — needed around a `Collapsible`.
  </Property>
</Properties>

### Structural parts

<Properties>
  <Property name="Sidebar.Header / Content / Footer" type="div">
    The three stacked regions. `Content` scrolls with the restyled native
    scrollbar; `Header` and `Footer` stay put.
  </Property>
  <Property name="Sidebar.Group / GroupLabel" type="div">
    A titled section. The label fades out as the rail collapses.
  </Property>
  <Property name="Sidebar.Menu / MenuItem / MenuSub / MenuSubItem" type="ul, li">
    The list structure. `Menu` is a `<ul>`; the buttons supply their own `<li>`
    unless you pass `unwrapped`.
  </Property>
  <Property name="Sidebar.MenuBadge" type="BadgeProps">
    The trailing chip on a row — literally `<Badge variant="count">`, with the
    one rule the sidebar adds: it disappears when the rail collapses.
  </Property>
  <Property name="Sidebar.MenuChevron" type="span">
    The rotating chevron for a collapsible branch.
  </Property>
  <Property name="Sidebar.Collapsible / CollapsibleTrigger / CollapsibleContent" type="—">
    A nested section wired to the rail animation.
  </Property>
  <Property name="Sidebar.Trigger" type="button">
    The toggle. Takes `icon` to replace the default glyph.
  </Property>
  <Property name="Sidebar.Rail" type="button">
    The hairline seam, doubling as a click target.
  </Property>
  <Property name="Sidebar.Inset" type="main">
    The content column that sits next to the sidebar.
  </Property>
  <Property name="Sidebar.Label" type="span">
    Text that fades out as the rail collapses. Exported so a custom row can
    join the same animation.
  </Property>
</Properties>
