# Quickstart

Run the creator, start the generated app, then check its public API. You'll
need Bun 1.4.3+ for the generated `dev` and CLI scripts, even if you install
packages with npm, pnpm or Yarn.

## Create a project

Choose a framework, theme, deployment target, database and package manager when
prompted. Cloudflare uses D1, Vercel uses PostgreSQL, and **Configure later**
supports SQLite or PostgreSQL.

<CodeBlockGroup defaultValue="bun" variant="line">
  <CodeBlock language="bash" title="bun">
    {`bun create @heyo-sh/heyo-status`}
  </CodeBlock>
  <CodeBlock language="bash" title="npm">
    {`npm create @heyo-sh/heyo-status@latest`}
  </CodeBlock>
  <CodeBlock language="bash" title="pnpm">
    {`pnpm create @heyo-sh/heyo-status`}
  </CodeBlock>
  <CodeBlock language="bash" title="yarn">
    {`yarn dlx @heyo-sh/create-heyo-status`}
  </CodeBlock>
</CodeBlockGroup>

## Start the page

Follow the commands printed by the creator. With Bun, for example:

```bash
cd my-status-page
bun dev
```

If you skipped dependency installation in the creator, install the project's
dependencies first. For SQLite and Vercel/PostgreSQL, `bun dev` starts a local
scheduler and runs the first check. Cloudflare/D1 projects run a Worker with
cron triggers instead; they have no `check` or `db:seed` scripts.

Open the page, then replace the starter's `example.com` monitors before you
publish it. You don't need a global CLI install to start the generated app.

<Callout type="info" title="The config is the source of truth">
  The routes, scheduler and CLI use <code>heyo-status.config.ts</code>, which
  also contains the database path or connection string. Do not commit production
  tokens or credentials; configure them from a private secret source.
</Callout>

## Check that it works

With the project running, try its public endpoints (adjust the port for your
framework):

```bash
curl http://localhost:3000/api/heyo-status/healthz
curl http://localhost:3000/api/heyo-status/status/summary
```

For SQLite and Vercel/PostgreSQL starters, `bun run check` also runs a check
manually without a global CLI install. Apply PostgreSQL migrations with
`bun run db:migrate` before publishing. For Cloudflare/D1, follow the
[Worker and Wrangler instructions](https://heyo.sh/heyo-status/deploying/cloudflare)
instead of using the local check script.

## Add it to an existing application

If you already have an app, install the package in its project root:

<CodeBlockGroup defaultValue="bun" variant="line">
  <CodeBlock language="bash" title="bun">
    {`bun add @heyo-sh/heyo-status`}
  </CodeBlock>
  <CodeBlock language="bash" title="npm">
    {`npm install @heyo-sh/heyo-status`}
  </CodeBlock>
  <CodeBlock language="bash" title="pnpm">
    {`pnpm add @heyo-sh/heyo-status`}
  </CodeBlock>
  <CodeBlock language="bash" title="yarn">
    {`yarn add @heyo-sh/heyo-status`}
  </CodeBlock>
</CodeBlockGroup>

Create `heyo-status.config.ts` at the application root. Then mount a catch-all
route at `/api/heyo-status`, render a fresh snapshot with `<StatusPage />`, and
schedule the checks. Follow the guide for your framework for the route and
layout files:

For a full command list, global CLI installation and exit codes, see the
[CLI guide](https://heyo.sh/heyo-status/cli). A generated project's package
scripts can use the project-local binary; direct `heyo-status …` commands in
your shell need a global install and Bun 1.4.3+.

When you're ready, deploy to [Cloudflare](https://heyo.sh/heyo-status/deploying/cloudflare),
[Vercel](https://heyo.sh/heyo-status/deploying/vercel) or
[self-host](https://heyo.sh/heyo-status/deploying/self-hosting).
