# Astro

Use `create-heyo-status` to generate a server-rendered Astro page, live API,
React island, database setup and scheduler wiring. Choose a Cloudflare or
Vercel deployment overlay for production cron jobs. A static Astro build
cannot serve current status or run checks. Astro 7 requires Node.js 22.12+
for local builds and Node deployments.

## Create a project

Pass `astro` to select the framework. Without flags, the creator asks for
the framework, deployment, database, theme and package manager.

<CodeBlockGroup defaultValue="bun" variant="line">
  <CodeBlock language="bash" title="bun">
    {`bun create @heyo-sh/heyo-status my-status-page --template astro
cd my-status-page
bun dev`}
  </CodeBlock>
  <CodeBlock language="bash" title="npm">
    {`npm create @heyo-sh/heyo-status@latest my-status-page -- --template astro
cd my-status-page
npm run dev`}
  </CodeBlock>
  <CodeBlock language="bash" title="pnpm">
    {`pnpm create @heyo-sh/heyo-status my-status-page --template astro
cd my-status-page
pnpm dev`}
  </CodeBlock>
  <CodeBlock language="bash" title="yarn">
    {`yarn dlx @heyo-sh/create-heyo-status my-status-page --template astro
cd my-status-page
yarn dev`}
  </CodeBlock>
</CodeBlockGroup>

The generated scripts and CLI require Bun 1.4.3+ even if you use another
package manager. If you skipped dependency installation, install the project's
dependencies first. Replace the example monitors in `heyo-status.config.ts`.
With Vercel/PostgreSQL, `bun dev` starts the local scheduler and `bun run check`
runs one check; Cloudflare/D1 uses Worker cron triggers in production instead.

## Customise the generated Astro project

- `heyo-status.config.ts` defines the database, monitors, schedule and theme.
- `src/pages/api/heyo-status/[...path].ts` serves the API. Keep its route path
  aligned with the config's `basePath` (default `/api/heyo-status`).
- `src/pages/index.astro` renders the latest snapshot on the server and
  hydrates the interactive React UI. Keep server rendering enabled; the status
  API and page cannot be prerendered.
- The deployment overlay provides the production cron. Keep its cron routes
  or Worker `scheduled` handler when changing the app.

On Cloudflare, use HTTP or DNS monitors: Workers cannot run native TCP/TLS
checks. On Vercel, Astro 7 needs Node.js 22.12+. See the
[Cloudflare](https://heyo.sh/heyo-status/deploying/cloudflare) and
[Vercel](https://heyo.sh/heyo-status/deploying/vercel) guides before deploying.
